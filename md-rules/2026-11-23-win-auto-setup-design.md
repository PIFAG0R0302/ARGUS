# Специфікація проєкту: WinAutoSetup (Rust + Slint)

**Дата:** 2026-11-23  
**Статус:** На погодженні  
**Мова / стек:** Rust + Slint (нативний GUI з CPU software-рендером) → один самодостатній `WinAutoSetup.exe` (`x86_64-pc-windows-msvc`)

---

## 1. Мета та контекст

Створити одну портативну `.exe` програму для Windows 10 та Windows 11, яка лежить на завантажувальній флешці **Ventoy** і закриває повний цикл автоматизації встановлення та початкового налаштування Windows на різних ПК із різним залізом:

1. **Підготовка флешки Ventoy:** налаштування прапорців і генерація `autounattend.xml` з автоматичною прив'язкою до вибраних Windows `.iso` у `ventoy/ventoy.json`.
2. **Автоматичний пост-інстал після першого входу в Windows:** автозапуск тієї самої `WinAutoSetup.exe` для вибору користувацьких паків програм (`winget` + локальні `.exe`/`.msi`), застосування системних твіків Windows і запуску **Snappy Driver Installer (SDI / SDIO)** для автоматичного встановлення драйверів під конкретне залізо.

### Ключові вимоги та обмеження
- **Один готовий `.exe`:** без сторонніх DLL, без потреби встановлювати .NET, Python, Node.js чи WebView2/Edge на чистій Windows.
- **Робота без відеодрайверів:** нативний інтерфейс на `Slint` із CPU software-рендером гарантовано запускається на `Microsoft Basic Display Adapter` до встановлення драйверів відеокарти.
- **Права адміністратора:** вбудований Windows UAC manifest (`requireAdministrator`).
- **Безпека даних:** у `autounattend.xml` за замовчуванням увімкнений **ручний вибір диска** (опція авто-розмітки Disk 0 вимкнена й вимагає явного прапорця).
- **Самостійне складання паків:** користувач сам створює, редагує та видаляє власні паки з каталогу програм; усі налаштування зберігаються в `config.json` поруч із `.exe`.

## 2. Структура на флешці Ventoy та життєвий цикл

```text
<Ventoy USB>:\
├── Win10.iso / Win11.iso              # Образи Windows
├── ventoy\
│   ├── ventoy.json                    # Оновлюється програмою (секція auto_install)
│   ├── ventoy.json.bak                # Автоматичний бекап перед зміною
│   └── autounattend\
│       └── autounattend.xml           # Згенерований файл відповідей
└── WinAutoSetup\
    ├── WinAutoSetup.exe               # Один готовий бінарник
    ├── config.json                    # Каталог програм, власні паки, прапорці XML і SDI
    ├── apps\                          # Локальні офлайн-інсталятори (.exe / .msi)
    └── logs\                          # Логи розгортання: setup_YYYYMMDD_HHMMSS.log
```

*(Snappy Driver Installer може знаходитись у будь-якій папці на флешці — програма автоматично шукає `SDI_x64*.exe` / `SDIO_x64*.exe` до глибини 3 рівнів від кореня флешки або використовує шлях, заданий користувачем.)*

### Сценарії запуску одного `.exe`
1. **Звичайний запуск (`WinAutoSetup.exe`):** відкривається на вкладці **«1. Ventoy & XML»** (при цьому всі 4 вкладки доступні одразу — можна запускати на вже встановленій Windows для програм, твіків чи драйверів).
2. **Автозапуск після встановлення Windows (`WinAutoSetup.exe --post-install`):** викликається з `<FirstLogonCommands>` у `autounattend.xml` через пошук файлу `\WinAutoSetup\WinAutoSetup.exe` на всіх томах `D:`–`Z:`. Одразу відкриває вкладку **«2. Паки програм»** для швидкого розгортання.

## 3. Функціональні модулі (4 вкладки інтерфейсу)

### 3.1. Вкладка «1. Ventoy & XML» (`autounattend.xml`)
Ручне налаштування всіх ключових прапорців із попереднім переглядом XML:

- **Мова та регіон:**
  - Мова інтерфейсу (`uk-UA`, `en-US`, `ru-RU`).
  - Розкладки клавіатури (наприклад, `0409:00000409;0422:00000422` — EN + UK).
  - Часовий пояс (за замовчуванням `FLE Standard Time` — Київ).
  - Назва ПК (опційне поле; якщо порожнє — генерується Windows).
- **Обхід обмежень Windows 11 (`windowsPE` → `RunSynchronous`):**
  - Окремі прапорці: `BypassTPMCheck`, `BypassSecureBootCheck`, `BypassRAMCheck`, `BypassCPUCheck`, `BypassStorageCheck`.
- **Обхід Microsoft Account та BitLocker (`specialize` → `RunSynchronous`):**
  - Прапорець `BypassNRO` (локальне встановлення без інтернету та облікового запису Microsoft).
  - Прапорець `PreventDeviceEncryption` (вимкнення примусового автошифрування BitLocker).
- **Акаунт та OOBE (`oobeSystem`):**
  - Ім'я локального адміністратора (за замовчуванням `User`), опційний пароль (може бути порожнім).
  - Прапорець `AutoLogon` (1 автоматичний вхід для пост-інсталу).
  - Прапорці OOBE: приховати EULA, приховати екран Wi-Fi, приховати екрани приватності (`ProtectYourPC=3`), приховати реєстрацію OEM та онлайн-акаунтів.
- **Розмітка диска:**
  - За замовчуванням: **Ручний вибір диска** (секції `<DiskConfiguration>` та `<InstallTo>` не додаються — інсталятор безпечно зупиняється на виборі розділу).
  - Опційний прапорець із візуальним попередженням: **Авто-розмітка Disk 0 (UEFI/GPT: 100 МБ EFI + 16 МБ MSR + решта NTFS)**.
- **Автозапуск після встановлення:**
  - Прапорець «Запускати `WinAutoSetup.exe --post-install` при першому вході» (додає PowerShell-команду пошуку флешки у `<FirstLogonCommands>`).
- **Інтеграція з Ventoy:**
  - Автовизначення кореня флешки Ventoy (за наявністю папки `ventoy\` або кореня диска, де лежить `.exe`) + кнопка вибору диска вручну.
  - Сканування `.iso` файлів на флешці з чекбоксами для вибору потрібних образів.
  - Кнопка **«Зберегти XML і оновити Ventoy»**: записує `/ventoy/autounattend/autounattend.xml` і оновлює секцію `auto_install` у `/ventoy/ventoy.json` (не торкаючись інших ключів конфігу Ventoy; перед записом створює `ventoy.json.bak`).

### 3.2. Вкладка «2. Паки програм» (Каталог + Конструктор паків)
- **Каталог програм** (вбудований базовий перелік `winget` + автоматичне сканування локальних `.exe`/`.msi` у `WinAutoSetup\apps\` + кнопка **«+ Додати програму»**):
  - Пошук та фільтрація за категорією (`Браузери`, `Утиліти`, `Офіс`, `Комунікація`, `Системні / Рантайми`, `Мультимедіа`, `Локальні`).
  - Кожен елемент має чекбокс вибору, назву, тип джерела (`winget` або `локальний`) та параметри тихого встановлення.
- **Конструктор власних паків (Presets):**
  - Користувач відмічає потрібні програми з каталогу і натискає **«Зберегти як пак»** (вводить назву, наприклад *«Офісний ПК»*, *«Ігровий»*, *«Ноутбук клієнта»*).
  - Список збережених паків дозволяє в один клік:
    - **Застосувати пак** (відмітити програми паку; можна комбінувати кілька паків).
    - **Оновити пак** поточним вибором чекбоксів.
    - **Видалити пак**.
  - Усі користувацькі паки та додані програми зберігаються в `config.json`.
- **Логіка встановлення:**
  - Перед встановленням `winget`-пакетів перевіряється доступність мережі та наявність `winget.exe`. Якщо інтернету немає — онлайн-програми акуратно позначаються як «Пропущено (немає мережі)», а локальні інсталятори встановлюються нормально.
  - Команда `winget`: `winget install --id <ID> -e --silent --accept-package-agreements --accept-source-agreements --disable-interactivity`.
  - Локальні `.msi`: `msiexec /i "<path>" /qn /norestart` (або користувацькі аргументи).
  - Локальні `.exe`: `"<path>" <silent_args>` (наприклад, `/S`, `/VERYSILENT /NORESTART`).

### 3.3. Вкладка «3. Твіки Windows»
Усі твіки — незалежні чекбокси, згруповані за категоріями (ідемпотентні, безпечні до повторного запуску):
- **Приватність і телеметрія:**
  - Вимкнути телеметрію (`AllowTelemetry = 0`).
  - Вимкнути рекламний ID та персоналізовані поради.
  - Вимкнути Copilot / Recall (Windows 11).
  - Вимкнути історію активності та рекомендації в меню «Пуск».
- **Деблоат (очищення UWP):**
  - Видалити стандартні непотрібні додатки (Bing News, Bing Weather, Solitaire, Clipchamp, Cortana, Feedback Hub, People, GetHelp).
  - Окремий прапорець: видалити OneDrive.
- **Інтерфейс і Провідник:**
  - Класичне контекстне меню Windows 11.
  - Показувати розширення файлів.
  - Показувати приховані файли.
  - Відкривати Провідник на «Цей ПК».
  - Вимкнути віджети та кнопку чату на панелі задач.
- **Система та продуктивність:**
  - Схема живлення «Висока продуктивність» (`powercfg`).
  - Увімкнути довгі шляхи (`LongPathsEnabled = 1`).
  - Вимкнути гібернацію (`powercfg /h off` — опційно).
  - Вимкнути швидкий запуск Fast Startup (опційно).
  - Вимкнути примусове автоперезавантаження після Windows Update при активних користувачах.

### 3.4. Вкладка «4. Драйвери (Snappy Driver Installer)»
- Автоматичний пошук `SDI_x64*.exe` / `SDIO_x64*.exe` на флешці Ventoy + можливість вказати шлях вручну.
- Прапорці запуску:
  - Автоматично встановлювати відсутні й новіші драйвери (`-autoinstall -autoclose -license`).
  - Не створювати точку відновлення (`-norestorepnt` — увімкнено за замовчуванням для швидкості на чистій ОС).
  - Додаткові аргументи CLI (текстове поле, за замовчуванням порожнє).
  - Перезавантажити ПК після завершення **всієї** черги (виконується програмою наприкінці після програм, твіків і SDI, щоб не переривати встановлення софту).

### 3.5. Спільна панель виконання (внизу вікна)
- Кнопка **«Запустити вибране»** (послідовно виконує: Програми → Твіки → Snappy Driver Installer → опційне перезавантаження).
- Кнопка **«Зупинити»** (акуратно перериває чергу та завершує активний дочірній процес).
- Прогрес-бар, поточний крок і згортана/розгортана панель живого логу (з автоматичним записом у `WinAutoSetup\logs\setup_YYYYMMDD_HHMMSS.log`).

## 5. Обробка помилок і надійність

- **Потоки та чутливість UI:** усі зовнішні процеси запускаються у фоновому `std::thread`; stdout/stderr читаються построчно й передаються у Slint через `slint::invoke_from_event_loop` + пишуться у файл логу.
- **Стійкість виконання (fail-soft):** помилка одного інсталятора або твіку логується з кодом повернення, але не зупиняє решту черги. Наприкінці виводиться зведений підсумок (*Успішно / Пропущено / Помилок*).
- **Атомарність запису (fail-fast для конфігів):** `config.json`, `autounattend.xml` і `ventoy.json` записуються через тимчасовий файл із подальшим перейменуванням; для `ventoy.json` попередньо створюється `ventoy.json.bak`.
- **Коректне кодування Windows:** при читанні виводу консольних утиліт Windows (`winget`, `reg`, `powercfg`) некоректний UTF-8 обробляється через `String::from_utf8_lossy` без панік.

## 6. Стратегія тестування та збірки

### 6.1. Автоматичні тести (`cargo test`)
Уся платформонезалежна логіка покривається unit-тестами, які запускаються на macOS і в CI:
1. **`autounattend.rs`:**
   - Валідність структури XML та екранування спецсимволів (наприклад, у паролі чи імені ПК).
   - Ручний вибір диска (відсутність `<DiskConfiguration>` і `<InstallTo>`) vs авто-розмітка Disk 0 (наявність UEFI/GPT розділів).
   - Увімкнення/вимкнення окремих прапорців (`BypassTPM`, `BypassNRO`, `BitLocker`, `FirstLogonCommands`).
2. **`ventoy.rs`:**
   - Створення нового `ventoy.json` з нуля.
   - Оновлення існуючого `ventoy.json` зі збереженням сторонніх полів (`theme`, `control`, `menu_alias`) і створенням `.bak`.
   - Сканування `.iso` та нормалізація шляхів у формат Ventoy (`/Win11.iso`).
3. **`config.rs`:**
   - Завантаження дефолтного каталогу, створення/оновлення/видалення користувацьких паків, round-trip серіалізація `config.json`.
4. **`apps.rs`, `tweaks.rs`, `drivers.rs`:**
   - Формування аргументів `winget`, `msiexec`, локальних `.exe` та `SDI`.
   - Автопошук `SDI_x64*.exe` / `SDIO_x64*.exe` у тимчасовому дереві директорій.

### 6.2. Збірка готового `WinAutoSetup.exe`
- **Таргет:** `x86_64-pc-windows-msvc`, профіль `release` (`lto = true`, `strip = true`, `opt-level = "s"` для компактного `.exe`).
- **Крос-компіляція з macOS:** через `rustup` + `cargo-xwin` (встановлює Windows SDK headers/libs локально без Homebrew та Visual Studio).
- **Додатково:** файл `.github/workflows/build-windows.yml` для відтворюваної нативної збірки на `windows-latest` за потреби.
