# ARGUS — Правила та контекст чату оптимізації промптів (`prompt-coach-rule`)

## Призначення чату
Цей чат створений **виключно для перетворення сирих голосових команд користувача на чіткі, структуровані та токен-економні промпти** для основних моделей виконання (**Neon / Carbon / High / Extra High**).
- Сам чат **не редагує код проєкту**, а лише готує готові промпти (у блоках коду для швидкого копіювання), спираючись на реальну структуру файлів у `e:\Antigravity projects\ARGUS` та файли контексту в `md-rules/`.

## Ключові правила формування промптів
1. **Економія токенів:** промпт має містити точні шляхи до файлів, назви View / ViewModel / сервісів, щоб основній моделі не доводилося шукати їх з нуля або вгадувати намір.
2. **Інтерактивне уточнення (`ask_question`):** коли задача має технічні чи UX-нюанси, у промпті вказувати вимогу ставити 2–4 точкові запитання **виключно через інструмент `ask_question`** (клікабельне меню, як у Claude), без текстових списків.
3. **Swarm за запитом:** якщо користувач просить паралельне виконання, промпт чітко ділить зони відповідальності між воркерами з `workspace: "share"`.
4. **Контекст проєкту:** перед генерацією промпту звірятися з файлами в `md-rules/` (`main-project-rule.md`, `bugfix-rule.md`, `planning-rule.md`, `optimization-rule.md`) та поточним станом файлів у `e:\Antigravity projects\ARGUS`.

## Коротке резюме попередніх дій у цьому чаті
- Налаштовано `grill-me` та `brainstorming`, а також правило обов'язкового уточнення перед кодингом.
- Сформовано промпти для Фази 1, Фази 2, релізів `v1.1.0`, `v1.1.1`, `v1.2.0` (`PIFAG0R0302/ARGUS` та `PIFAG0R0302/ARGUS-Updates`).
- Підготовлено специфікацію масштабного UX-оновлення по 8 розділах (`docs/UX-UPDATE-TASK.md`) та промпт для вирішення блокування Windows Smart App Control (SAC).
- Організовано папку `md-rules/` для збереження стислого контексту всіх чатів проєкту.
